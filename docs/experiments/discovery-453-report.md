## Public pilot replay

The replay used the original **20 public pairs and 13 distinct MIT donor pins**,
with fresh receiving comparisons and immutable donor Git objects. It acquired no new
history, wiki or issue channels. Root MIT grants were re-read at each pin; registration
also rechecked path-level grants and notice provenance. No donor program, build,
package installer or test executed. There was no paid benchmark, scheduler or fleet run.

Each pair received one manually authored receiving-flow hypothesis, supported by
actual donor and receiving file ranges. The second selected facet is budget-deferred.
The bounded results are **one verified gap, nine scoped NO_GAP decisions, six specific
out-of-scope decisions and four specific not-useful decisions**. These describe the
inspected hypotheses, not every original menu card or the whole donor.

The additional non-trait gap is configuration error location. At
`python-jsonschema/jsonschema@c497561ea0a95f5aac09cd63d15eb1420eb7bbec`,
`jsonschema/exceptions.py:138-171` renders typed and escaped locations; tests at
`jsonschema/tests/test_exceptions.py:1063-1115` cover ambiguous names. Crab's receiving
`config_validation.py:83-103` reports an invalid scoring section without the member.
A local receiving baseline confirmed that `scoring.categories` with an invalid
`bad.key` value reports only the section. The registered
`crab:code:code.config-error-location` stays an **idea** under current hunger. Its
proposed small stdlib adaptation has explicit maintenance and acceptance criteria;
it is not an implemented or maintainer-accepted transfer.

Other concrete conclusions include keeping byte limits before whole-file buffering
(Repomix), retaining Crab's explicit immutable repository scope rather than provider
probing (Gitingest), finding existing bounded child cancellation (tox), existing
undecorated machine JSON (Rich/CLI), existing recursive public-help coverage (Typer),
existing preconstruction YAML cycle checks (Lark), and explicit network permission
(referencing). BeautifulRepo's inspected flows already bound audit reads and redirected
directories, identify catalog entries, and provide plain JSON; converter/recording
runtimes would break its offline contract. An interactive overwrite prompt would
obstruct its explicit, atomic generated-catalog workflow. A universal library README
order would erase its distinct audience-specific scaffolds.

The detailed public ranges, reasons, input/tool hashes, receiving commits and snapshot
identities are retained in [the replay JSON](discovery-453-replay.json). Review was
performed by the implementation session. No independent auditor or completed swarm
is claimed.

### Coverage and learning limits

The fresh **166 original structural candidates remain individually unreviewed**.
They were not mass-rejected merely because the bounded behavioral hypotheses had
outcomes. All 20 reports remain `exploration_complete: false`, with their deferred
facet and unreviewed denominator visible. Other facets, shallow history, wiki and
issues remain unexamined. Completing this bounded release replay does not claim
exhaustive donor exploration.

The original 109 public menu decisions, including 78 generic OUT_OF_SCOPE decisions
using eight reason strings, remain unchanged. Their lack of inspected source references
does not become individual review retroactively. The retained original judgement file
is bound by SHA-256 in the new public report.

The consumed Crab ledger contained 59 confirmed learning inputs without exploration
review evidence; BeautifulRepo's consumed ledger contained none. Ten stable IDs overlap
historically declined IDs, but **zero rejection votes have the pilot's generic reason
strings**. Stable-ID overlap cannot establish which earlier judgement produced a vote;
the ledger does not supply an invented event history. The replay writes no feedback or
scoring/policy changes. Existing legacy feedback remains visible and qualified.

## Validation and release boundaries

The full local Windows Python 3.11 run on implementation `057c03d` passed **3,733
tests**, with 43 platform/optional skips. The subsequently integrated #454 lexical
controls and additional acceptance regressions receive targeted checks and fresh
complete CI. Ruff, format and strict mypy were checked locally, including both Linux
and Windows target platforms. Frozen B1 retains `recall_must@30 = 1.00 (10/10)` and
`noise@30 = 0.66 (19/29)`; labels were not changed.

Fresh integrated CI must finish before merge/release: four actual Windows/Linux
Python 3.11/3.14 jobs, native hard-quota jobs on both operating systems, static checks,
source/wheel checks, base installation, installed CLI/plugin/stdio-MCP smoke checks,
and self-digest. PR publication, merge and final package release are distinct phase
observations; their final exact revisions/runs are recorded in the PR/release evidence.

Known limits remain explicit: approximate syntax rather than a universal parser;
bounded root package-script interpretation rather than arbitrary shell evaluation;
legacy unbounded catch without a selected volume; elevated rights to provision/verify
a Windows volume; a supervisor crash before Job assignment can leave a suspended
trusted child that has executed no Git code. #243 host enforcement/autonomy, paid B2,
Marketplace release and full cache GC remain excluded.
